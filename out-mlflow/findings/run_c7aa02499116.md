## 1. SSRF via unsanitized gateway_path appended to server-side target URI  
**Verdict:** `true-positive`  |  **Severity:** `high`  |  **Class:** CWE-918  |  **Rule:** `codeguard-py-ssrf`

- **Location:** `mlflow/server/handlers.py` - `gateway_proxy_handler` (line 1129)
- **Fingerprint:** `fp_6161a93af7d2a675`

The gateway_path value comes directly from external input (request args or request JSON) and is interpolated verbatim into the outbound request URL with no allowlist, no scheme validation, no path normalization, and no blocking of special characters. Although target_uri is server-configured, a crafted gateway_path containing path-traversal sequences, encoded characters, or redirecting payloads could cause the server to issue requests to unintended internal paths of the target or, in environments where the requests library follows redirects, to entirely different hosts. The HTTP method is also fully caller-controlled (request_type = request.method), compounding the risk.

**Evidence (citations):**

- `mlflow/server/handlers.py:1129` - resolved
  > `gateway_path = args.get("gateway_path")`
- `mlflow/server/handlers.py:1135` - resolved
  > `request_type = request.method`
- `mlflow/server/handlers.py:1138` - resolved
  > `response = requests.request(request_type, f"{target_uri}/{gateway_path}", json=json_data)`
